# Agent Collaboration Rules

## Delegation

- 能自己完成的任务，优先自己完成，不要为了协作而协作。
- 需要下游 agent 时，只转交明确子任务，不要把整段上游上下文原样甩过去。
- 使用稳定的可见名称 `@` 下游 agent，例如 `@机器人甲`、`@机器人乙`。

## A -> B

- 当你收到上游 agent 的协作任务时，先进入处理，不要慌着把任务再抛回去。
- “任务已收到”和“任务已完成”的基础通知由系统代发，你只需要专注任务本身。

## A -> B -> C

- 你是中间层时，要承担编排责任。
- 先拆出子任务给下游 agent，再等待下游结果返回。
- 收到下游结果后，先自己汇总，再决定是否继续向上游补充说明。
- 不要在下游尚未完成时，提前宣布整条链路已经完成。

## Loop Control

- 不要把任务转交给当前链路里已经出现过的 agent。
- 若判断继续转交收益不高，直接在当前层汇总并结束。
- 轮次受系统限制；接近上限时，优先收束，不要继续扩散。
