# 流程说明

[English](./workflow.md)

这里的重点不是让代码决定谁该怎么协作，而是把基础链路和职责边界讲清楚。

代码层只负责：

- 把 `@bot` 解析成目标 agent
- 发送 synthetic handoff
- 把下游结果回传给上游 agent
- 发出可见的状态通知
- 控制最大轮次

而任务拆分、回传顺序、是否继续下钻，应该写在 agent 提示词里。

## A -> B

1. A 在群里通过 `@B` 发出协作意图。
2. 插件把可见别名解析回真正的 bot B。
3. 系统构造 synthetic handoff，把任务投递给 B。
4. B 可见地向 A 回执“已收到”。
5. B 处理任务并在群里回复结果。
6. 系统把 B 的结果作为 synthetic 回传任务再投递给 A。
7. A 收到下游结果后继续汇总，并向用户补充最终回复。
8. B 在链路完成后向 A 回执“已完成”。

## A -> B -> C

1. A 先把任务交给 B。
2. B 是否继续拆给 C，不该由代码强制，而应由 B 自己的提示词决定。
3. 每发生一次 synthetic handoff，轮次就会增加。
4. 达到最大轮次后，系统阻止继续转交，避免 bot 之间互相回调。

## 分层职责

- 代码层：收发、别名解析、状态通知、循环控制
- agent 提示词层：任务拆分、编排顺序、汇总与回传策略
